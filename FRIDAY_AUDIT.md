# FRIDAY audit

## How it works today

FRIDAY builds your class schedule from a weekly timetable, one-date changes and dated availability facts.
The College Schedules window edits those same records. Assignments and exams share a deadline file, and college events have their own file.
Ordinary reminders are separate SQLite records. The scheduler checks for due reminders every five seconds and checks current context before sending.
A dated class or deadline move can propose shifting explicitly linked reminders. An apply command commits the shift.
“Move/cancel/change my reminder because I have another class” lacks the information the general reminder matcher uses. A normal conversation reply does not perform that edit.
Personal facts live in several stores with different rules for corrections, recall and expiry.

```text
Island / chat / voice -> intent and reference matching -> local handler
    "what's my next class?" -> timetable reader -> weekly + dated changes + facts -> reply
    "remind me at 5pm to leave" -> reminder writer -> SQLite -> acknowledgement
                                                   -> scheduler poll + current context
                                                   -> toast / eligible Telegram / optional speech
    "tomorrow's DBMS class moved to 11 AM" -> dated class writer -> occurrence JSON
                                                   -> linked proposal -> preview reply
      explicit apply -> SQLite time change -> scheduler reads the new time
    unmatched request -> optional model translation and approval, or conversation reply
```

Scope is the live working tree, including existing uncommitted changes, and the single-owner laptop setup with optional remote channels. Examples below are fabricated from source schemas. I used the existing graph for navigation and verified line numbers against live files. This is a static audit. The installed app, actual user records, model output and runtime configuration were unverified.

## 6. Scheduler

## 10. Bugs and risks observed in source

1. **Cancel can hit a different reminder.** “Cancel reminder 1” relists before deletion. A new earlier reminder can take that position after the user last saw the list. The parser also takes any first digits in a reason such as “cancel my reminder because class starts at 2,” which can select position 2. The final SQL delete matches only ID and ignores row count and delivery status. `services/automation/intent.py:267` · `services/reminders/service.py:142,160`
2. **A weekly edit can hide a valid dated move.** A user removing a weekly slot or changing a field such as room changes the full template identity. `effective` then stops applying the old occurrence row. An explicitly linked reminder can keep deferring because the old template is absent. `services/college/schedules.py:52` · `services/proactive/class_sessions.py:59,70,97` · `services/proactive/class_changes.py:65`
3. **Holiday disagreement.** A holiday stored by the attendance path is honored by the schedule adapter and linked reminders, but `next_class_occurrence`, `classes_for_date` and dated class recall themselves don't check that holiday list. 4. **Overlaps can enter through two paths.** Direct weekly add can create overlapping rows without `validate_rows`. 5. **Two reminder move implementations have different race protection.** Linked apply checks active leases and channel status and clears delivery state in its transaction. Reasoning apply updates SQLite directly without those guards. 7. **An old explicit memory can win semantically.** A close contradiction can take the duplicate-strengthening branch. ## Gaps

1. Generic reminder rescheduling by ordinary text is absent from the local reminder matcher, and the legacy tool definitions expose only create/list/cancel. `services/automation/intent.py:249` · `services/automation/command_tools.py:148`
2. “My reminder” is neither a stable target nor a supported cancel selector. A reason such as “another class” supplies neither the target nor a new due time. `services/automation/intent.py:260` · `services/reminders/service.py:142,160`
3. Ordinary reminder creation records a task and due time with no automatic link to the class or deadline it mentions. `services/reminders/service.py:87,105,123` · `services/proactive/deadline_reminders.py:106`
4. Explicitly linked reminders hold their old times until a current proposal is applied. The approval is scoped, and no blanket permission replaces it. `services/proactive/deadline_reminders.py:46,68,126`
5. Separate generic reasoning proposals require model/evidence availability and explicit approval for a reminder move. They do not connect a casual class statement directly to a reminder edit. `services/mind/reasoning.py:499,541,601,747` · `services/mind/reasoning_commands.py:76`
6. Typed timetable updates have narrow shape: add/remove/clear weekly slots, move an existing named occurrence on one date, or record availability. A cross-date move or one-off extra class is absent from those writers. `services/proactive/timetable.py:319,380` · `services/proactive/class_changes.py:26,104` · `services/memory/schedule.py:49`
7. The normal fallback can translate, clarify or reply, with action execution reserved to the guarded router. Chat history is separate from academic and reminder writes. `services/automation/intent.py:876` · `services/mind/language.py:62` · `interfaces/api/routes/chat.py:343,377`
8. No shared, deterministic schedule conflict resolver was found across weekly slots, dated moves and reminder writers. `services/college/schedules.py:44,68` · `services/proactive/class_changes.py:104` · `services/proactive/deadline_reminders.py:68`
9. Personal facts have separate authorities with different supersession and expiry semantics, so a remembered statement does not necessarily update the class, reminder or old fact that the next workflow reads. `services/memory/sqlite_memory.py:171` · `services/memory/semantic.py:278` · `services/memory/schedule.py:107,139` · `services/mind/temporal_memory.py:351`
10. The existing autonomy levels and verified receipts cover selected effects. No integrated autonomous calendar/ordinary-reminder editor or general undo for those changes was found in the autonomy, presence, College and reminder dispatch paths. `services/automation/autonomy.py:15,148,341` · `services/presence/commands.py:77` · `services/college/service.py:15` · `services/reminders/service.py:123`
