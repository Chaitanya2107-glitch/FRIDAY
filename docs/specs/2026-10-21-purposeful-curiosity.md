# Purposeful curiosity: phase 4 first increment

Extend the existing local inquiry engine. Enumerate bounded, source-linked gaps
for task blockers and undated/uncertain owner commitments. Rank current focus and
high-priority work ahead of background gaps. These are missing fields, never canned
questions. Setting mismatches belong to local controller investigation, not asking
the owner for settings FRIDAY can read. No gap means silence without inference.

A generated question must name a supplied gap, the decision its answer would
change, two distinct conditional next steps, and why asking now helps. Background
interest alone is insufficient. The model may choose silence regardless of ranking.
Existing local notification review sees this purpose; no extra inference loop or
provider/configuration changes. All content remains data, not tool authority.

Persist the chosen gap identity, semantic source version and purpose in existing
inquiry job receipts. Reuse their bounded 200-job history for suppression. Answered,
declined, unanswered and already offered/prepared versions cannot be asked again
automatically while retained. Meaningful task/commitment changes can reopen a gap;
timestamps, new receipt IDs, unrelated activity and paraphrasing cannot. Reopening
never bypasses the shared 45-minute gap, three/day ceiling, quiet/attention gates,
lease, source recheck or notification review. Explicit requested questions remain
one scoped reply and can fall back to a request-context gap without starting a chain.

Answers remain original owner episodes; answering a gap never claims the task was
unblocked/completed or that an action ran. Forgetting clears private gap/purpose
receipts and fences in-flight acceptance; anonymous interruption budgets remain.
Last-minute delivery rechecks the semantic gap too. Legacy job schema/data migrate
additively. Brain status and the existing local brain API explain purpose and
conditional next steps without exposing them to Telegram or generic public events.

Test ranking, no-gap/no-benefit silence, already-known dates, answered closure,
meaningful reopening and noise, restart, stale source/delivery, quiet/budgets,
forget/concurrency and actual answer/delivery paths. Use deterministic provider
doubles plus a bounded synthetic installed-Ollama probe with no notifications or
OS actions. Run focused and full regressions after final review.

Limits: first increment covers task blockers and missing commitment dates, with
at most eight supplied gaps and the existing 200-job history. Semantic usefulness
is model-assessed and may abstain. This does not infer all unknown facts, automatic
repair, task completion or human consciousness. Phase 5 is memory consolidation.


## Implementation details and live evidence

Question text is always generated by the existing local inquiry model; eight is a
maximum open-gap context size after closure filtering, not a question target. Relevant
source projections ignore clock/receipt noise and task text case/punctuation; they
cannot prove arbitrary source paraphrases equivalent. Conflicting active commitment
identities are withheld. Retained latest closed versions can reopen after another
relevant source change, including return to an earlier blocker. No question itself
creates a new automatic knowledge gap.

Purpose uses typed possible-answer/next-step objects. Both answers and actions must
differ, contain readable content, cite a supplied source, and affect a useful decision.
The purpose field is required in model output and null for silence. Existing optional
feature questions retain their established notification contracts and global budgets;
this increment's gap selection covers generated inquiry, task blockers and missing
commitment dates, not every feature-specific question type.

Additive serialized migration preserves old jobs. Answered/ignored/shushed reactions
are terminal against delayed delivery updates. Up to four question-review receipts
enter shared local reasoning; branches remain proposals rather than facts or completed
tasks. last_question diagnostics survive later silent last_decision updates. Private
review conclusions do not enter remote prompts/mirrored offers, and local inquiry
notification-review events are private. All source/lease/epoch/attention/budget gates
remain effective; there is no extra inference loop or automatic tool authority.

Live final workflow: tasks/curiosity-shipped-live-probe.json. Installed local
qwen2.5:3b-instruct-q5_K_M prepared one decision-relevant question; after an isolated
recorded answer the automatic opportunity used zero model calls. A changed blocker
under a synthetic two-hour clock reopened the gap. Actual local notification review
approved both preparations; there were no delivered notices or OS commands. Total
workflow time was 13.40 seconds. A frozen-candidate control approved useful unknown
information and rejected an already-known answer. Earlier trials exposed optional
purpose omission, identical next steps and inconsistent reviewer booleans. Typed
contracts reject invalid output. A neutral boolean instruction replaces the fixed-false
example without interpreting prose as approval. The frozen replay did not consistently
reproduce the old mismatch, so the local model's calibration remains a limitation,
not a claim of reliable human judgment. Earlier probe artifacts remain diagnostic.
