## 1. Temporal memory and a shared situation model — first increment implemented

Use the existing local executive review to interpret dated owner dialogue into
source-linked commitments. Resolve relative dates against the original receipt
date. Preserve revisions, uncertainty, completion and cancellation. A correction
must target the same commitment and must not silently overwrite unrelated facts.
Expose the same bounded current/past/upcoming/unresolved view to reasoning,
conversation, inquiry, notifications and the life engine. These are interpretations
of owner reports, not independently verified events or permission to act.

Acceptance: “My exam is tomorrow” remains anchored across restart; “it was
postponed” removes the superseded date from the current view while retaining
history; ambiguous corrections preserve uncertainty; invalid or stale model
output changes nothing; forgetting clears this derived private state.

## 2. Behavioral life state — first increment implemented

Connect responsibilities, engagement, uncertainty and interruption preferences
to decisions about investigation, restraint and conversation. Learn timing from
feedback. Keep persona mood separate from evidence and service success.

Acceptance: a busy owner or declined conversation reduces interruptions; silence
does not create an obligation to answer or a fabricated emotional grievance.

## 3. Verified outcome learning - first increment implemented

Record expected results, verify observable effects and use mismatches to adjust
future decisions. Build on existing executor receipts and prediction scores.

Acceptance: mode/integration reports distinguish requested, applied, verified,
failed and unknown; repeated failure changes the next plan or explanation.

## 4. Purposeful curiosity - first increment implemented

Rank unresolved questions by relevance, expected usefulness and whether an answer
would change a decision. Reopen resolved topics only after meaningful changes.

Acceptance: no question quota or automatic interview chain; explain the evidence
gap and why asking now is useful; changed circumstances can reopen an old topic.

## 5. Memory consolidation - first increment implemented

During suitable idle periods, connect related experiences, summarize ongoing
situations and retire obsolete assumptions with provenance and forget support.

Acceptance: summaries cite originals, corrections survive retention, summaries
cannot promote model guesses into owner facts, and consolidation respects local
inference budgets and gaming/attention deferral.

## 6. Local inference reliability - first increment implemented

Measure cold model load, prompt processing, generation and critique separately on the
installed model. Make useful reviews fit the existing attention/inference resource limits
with compact context and measured runtime behavior. Preserve local thinking and gaming
protection. Avoid a new background loop, model downloads or silent cloud/budget changes.

Acceptance: repeated synthetic cold/warm reviews complete generation, independent critique
and guarded persistence, retaining uncertainty and dates. Report latency components and
honest unavailable states. Relevance-based recall is a later follow-up: retrieve older
useful sources without reintroducing corrected assumptions or recursive summaries.

## 7. Relevance-based recall - first increment implemented

After phase 6 follow-up controls, retrieve older relevant original reports and reviewed
threads within existing context/storage limits. Prefer provenance-preserving selection
over another generated summary layer. Superseded/forgotten evidence must stay excluded;
a semantically relevant memory is historical evidence, never current state or permission.
Reuse existing local evidence and correction chains; measure recall against unseen queries,
including cases where no source is relevant. Do not add a continuous model loop.

## Implementation constraints

Thinking stays local through the configured Ollama stack. Existing AI language
providers remain available for conversation. Reuse persistence, review budgets,
attention checks and permission boundaries. No new model downloads, billing
changes or continuous inference loop are needed for these phases.
