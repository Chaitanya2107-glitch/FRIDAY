# HUD implementation contract

Root is the sole writer; two researchers inspect native and Python contracts.
Existing owner edits stay in place. No commit, push, or publication.

Use a small independent HUD WebView, reusing the Island's authenticated connection
and forwarding data through native events. No duplicate WebSocket/SSE connection.
Native visibility blocks fullscreen and locked desktops independently of polling.
Only visible HUDs request one-second cached system figures; saver uses five seconds.
Optional schedule/activity services are queried at use time. Slow state is
refreshed on existing events and periodically to recover missed events.

Settings live in the HUD plugin's normal user-data settings. Geometry uses logical
monitor-relative coordinates; disconnected monitors fall back to primary. Native
edit mode exposes explicit drag/resize controls and captures geometry on Done.
Tauri's persistent always-on-bottom Windows implementation is the first desktop
strategy. Test its actual Z order before accepting it; document OS coverage.

Boot is a two-second, cancellable sequence once per authenticated backend epoch,
with a simple fade for reduced motion. There is no audio or renderer animation
loop at rest. Preserve Mochi's existing artwork and interactions.

Acceptance: token/schema/cache tests; command/settings, optional-service privacy,
visibility and saver tests; frontend build/unit tests; Rust checks; native
click-through/edit/fullscreen/Z-order checks; measured idle process-tree CPU below
2% machine-normalized (Windows Task Manager convention) and HUD private working
set increase below 100 MiB. Also report unnormalized core CPU, RSS, total and
incremental memory, warmup/window and hardware; never compare unlike metrics.
