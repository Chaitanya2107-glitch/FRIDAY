# FRIDAY Island integration

The Island is FRIDAY's primary desktop surface. The existing desktop lifecycle
owns one backend; its API lifespan owns the authenticated Island transport.
The desktop controller retains voice/wake/conversation and proactive-question
ownership, native editors, and the trusted screen-awareness badge.

Assistant text uses the decorated canonical chat function with explicit local
authority and existing confirmations. Native app launching remains ID-based.
Private turns never enter Island persistence or notification mirrors. Backend
keyboard steps are held under expiring, socket-bound, one-use tokens and may
only apply to the original foreground process/window.

The Island shows authoritative runtime/voice state, bounded session conversation,
approved notifications, full feature entry points and shared project catalogs.
Existing native launch profiles retain their ordered actions. Import into the
FRIDAY catalog is additive and revision checked; conflicting names are reported.

One desktop delivery owner forwards questions/results; the Island never drains
the question queue. Windows reminders retain their delivery receipts and provide
identified display events to Island. Receiving an event does not imply reading it.

Acceptance: unified entry points and clean shutdown; authenticated local-only
commands; real note/confirmation/history paths; responsive stop controls; original
voice state machines; no private transcript persistence; safe typing target;
shared tracker/project data; editor access; screen badge/privacy preservation;
native offline apps/media and focus behaviour; isolated Python/TS/Rust checks,
frontend/native build, source-bound validation receipt.
